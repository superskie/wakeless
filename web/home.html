01 / The cost of size

One swap pays for its size.

Quote the same pair at $1,000 and at $500,000 in the same minute, and the large swap gets less per dollar. Above what the solvers fill at once, it gets no quote at all.

02 / The leak

Slicing in public is a broadcast.

Desks split large orders over time. Done from one public wallet, the split tells everyone watching how much is still coming.

  3. 04:430x7a3f...9c21 sells 31,250 USDC
  4. 13 more: same wallet, same size, every 1m 53s

An illustration: $500,000 in 16 equal slices from one wallet.

  • On Hyperliquid a TWAP is an on-chain action that carries the wallet, market, side, total size and duration.
  • On 7 Nov 2026 at 08:28 UTC a public tracker listed 416 running TWAPs with about $40M ordered.
  • An open-source library reports each slice of a tracked TWAP within about half a second.
  • Random sizes do not hide an order whose total is public.

  • What stays public is the way in and the way out.

03 / How a run works

Random slices, a hard floor.

One engine runs in the browser, on the command line and through the agent. The scheduler below is the desk's own, fed the same $500,000 order. Move it.

  1. ArrivalQuote a slice and the whole order at the same moment. The arrival price minus the move you accept is the floor; the whole-order quote is the benchmark.
  2. SlicesEach slice gets a random size and a random moment inside its own slot. The sizes add up to the order to the base unit, and the seed replays the schedule.
  3. FloorA slice executes only at or above the floor. Below it, the slice waits for a later slot, then stays unfilled; the floor is never lowered to finish. A slice that finds no liquidity splits in two. Live, the floor is also the swap's min_amount_out.
  4. ReportEvery decision goes to a journal with its raw quote, and the report is rebuilt from that journal alone, against one swap of the whole order quoted at arrival.

04 / Live mode

The wallet keeps the rules.

Live mode runs through an agent account on the NEAR Intents Agent API. The owner signs one policy, and the API enforces it on every request from the desk's grant, before anything reaches a solver.

The owner's key signs the rules. The desk holds a grant, which can not change them, so a leaked grant can only swap within the caps or pay the owner back.

The policy goes on chain encrypted, next to its hash; the cap is not readable there. The time of a change is public, so sign a cap well ahead of an order.

06 / Limits

What it does not do.

The edges of a hackathon build, stated plainly, so you can judge where it fits.

  • Fees still apply.Every fill pays the 1Click platform fee: 20 bps with a partner key, 1 bp on stablecoin pairs. It is a percentage, so slicing adds none, and the pre-trade check advises one swap when size costs nothing.
  • Private from the public, not from the operator.The Agent API that executes the swaps sees them. The public intents.near ledger does not.
  • The ends are public.The deposit and the withdrawal are ordinary transactions on their chains, and so is the time of every policy change.
  • The saving moves with the market.$500,000 cost 24.5 bps more than $1,000 on 5 Nov and 8.7 bps two days later. Run the pre-trade check right before an order.
  • A dry run sees a fresh market.Dry slices use up no liquidity. A real slice only finds the same depth if market makers refill between slices, and only a live run at size measures that.
  • The live run was small.At $6 there was no impact to avoid, so its slices got 15.5 bps less SOL than one swap. It proves the path; the $500,000 runs are dry runs on live quotes.
